# Пайплайн ассетов

В репозитории нет ни одного бинарного ассета. Всё, что видит и слышит игрок,
собирается Python-скриптами в `build/gen/` и компилируется как обычный C.

```
tools/pal.py ──────────────┬──> genpal.py   ──> build/gen/pal.h
                           │                    build/gen/paldata.c
                           ├──> gentiles.py ──> build/gen/tiles.c/h
                           ├──> genart.py   ──> build/gen/assets.c/h
                           └──> gencity.py  ──> build/gen/city.c/h
                                                build/preview_city.png

tools/vendor.py ──> genfont.py  ──> build/gen/font.c
genmusic.py     ──> build/gen/music.c  +  dist/RADIO/*.MID
genstrings.py   ──> build/gen/strings.h
genicon.py      ──> docs/banner.png, docs/icon.png, docs/icon.ico
```

Каждый генератор идемпотентен: два запуска дают байт-в-байт одинаковый
результат. Поэтому `build/gen/` можно не коммитить, и `git diff` после
пересборки пустой.

## Почему так

Обычный проект хранит спрайт как `.png` и конвертирует его в массив при
сборке. Здесь спрайт **описывается кодом**, потому что:

* `git diff` показывает, что изменилось в персонаже, а не «binary file
  changed»;
* палитра — единый источник правды, и «4-й зелёный» нельзя случайно
  заменить на «5-й зелёный» в одном файле;
* валидатор может отказаться собирать плохой ассет;
* проект остаётся читаемым через десять лет без просмотрщика спрайтов.

## Палитра

`tools/pal.py` определяет рампы: имя, список RGB-стопов, количество
ступеней. Индекс 0 всегда прозрачный.

```python
"neonpink": ([(92, 6, 44), (226, 30, 118), (255, 132, 196)], 8)
```

Из этого строятся:

* `PAL["neonpink4"]` — числовой индекс для C;
* `PAL_NEONPINK4` — макрос в `pal.h`;
* `RAMP_INFO` — обратная таблица «индекс → (рамп, ступень, всего)», по ней
  работает затемнение спрайтов.

`dim_index(idx, steps)` — ступень вниз по рампе. Не умножение цвета:
быстро и не выходит за пределы палитры.

## Тайлы

26 тайлов 16×16, каждый — маленькая функция с детерминированным шумом
(`h32(x, y, seed)`). Плюс две таблицы:

* `g_tile_flags[]` — `TF_SOLID`, `TF_ROOF`, `TF_WATER`;
* `g_tile_opaque[]` — есть ли в тайле прозрачные пиксели. Непрозрачные
  бл*итятся через `memcpy`.

## Спрайты

`tools/genart.py` рисует три категории.

**Люди** — ASCII-сетка 12×16 на четыре стороны, потом перекрашивается
в шесть персонажей заменой рамп. Одна сетка, шесть характеров.

**Машины** — строится одна машина по маске скруглённого прямоугольника
(кузов, стёкла, крыша, фары, колёса), потом **вращается** nearest-neighbour
в 16 положений. Вращать индексированное изображение можно, если никто
не интерполирует цвета.

**Пропсы и пикапы** — пальмы, баки, мусорные контейнеры, фонари, билборды,
деньги, чемодан, аптечка, броня, патроны, звезда розыска.

Итог: 153 спрайта, ~103 КБ пикселей, всё в `assets.c`.

## Шрифт

`genfont.py` берёт `unifont.hex.gz` и собирает таблицу 256×16 для CP866.
Это кодировка, которая была бы у русского DOS-гейма в 1994.

Дальше главное правило: **весь русский текст хранится как CP866-байты**,
экранированные в `\ooo`. Компилятор не может ничего испортить, какой бы
кодировки он ни придерживался, а редактор не перепишет файл в UTF-8
по-своему.

## Музыка

Песни написаны в ступенчатой нотации:

```
"5.7.8.7.5.3.2.3."   цифра = ступень, '.' = пауза, '=' = держать ноту
```

Каждый такт несёт смещение корня, поэтому четыре такта по i–VI–III–VII
пишутся сами.

`genmusic.py` выдаёт два файла из одного источника:

* `.MID` в `dist/RADIO/` — обычный Standard MIDI File (format 0, PPQ 96).
  Его можно открыть в любом плеере и услышать **референсный микс**;
* `music.c` — таблицы нот и делителей PIT.

Если игра звучит не так, `.MID` показывает, как должно быть.

## Город

`gencity.py` — самый большой генератор. Город не шумит, а **проектируется**:
таблица 6×6 задаёт район каждого квартала (даунтаун, пригород, пляж, доки,
парк, промзона), и у каждого района свой painter.

Порядок:

1. сетка дорог 4 тайла, разметка, зебры на перекрёстках, люки;
2. каждый квартал: тротуар, бордюры, потом содержимое;
3. пропсы, спавны машин, спавны пешеходов, пикапы;
4. **валидация**.

### Валидатор

После генерации:

1. от точки спавна заливается карта (flood fill);
2. каждая точка интереса придвигается к ближайшей **достижимой** клетке
   (`nearest_reachable`, а не `nearest_walkable` — замурованный двор тоже
   проходим);
3. если хоть одна точка недостижима, сборка падает с их списком.

Плюс предупреждение, если достижимо меньше 97% проходимых тайлов.

Именно это поймало торговый центр, у которого загрузочный док был запечатан
внутри здания: игрок видел маркер задания на стене.

## Иконка и баннер

`genicon.py` собирает `docs/banner.png` (960×636) и `docs/icon.png`
(256×256, плюс `.ico` на 6 размеров) из **той же палитры и того же
шрифта**, что и игра. Никакого внешнего графического редактора.

Баннер компонуется по горизонтальным зонам (небо → скайлайн → вода → песок
→ плашка → подписи), чтобы ничего не приходилось накладывать друг на друга.
Первая попытка наложила плашку на скайлайн и получила ряд парящих крыш.

Иконка — золотая «6» на закате. Вариант «VI» пришлось выбросить: у
Unifont'овской заглавной «I» есть засечки, и в 64×64 засечка — это вся буква,
поэтому получалось «VJ».
